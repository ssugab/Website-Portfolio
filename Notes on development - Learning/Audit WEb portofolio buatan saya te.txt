### 2. Temuan Kritis & Rekomendasi Perbaikan

#### A. Keamanan: Kredensial EmailJS Terpapar Langsung (*Hardcoded Credentials*)
* **Lokasi**: [src/components/ContactForm.jsx](file:///d:/Documents%20D/Code%20Program/Websites/Website%20Porto%20Learn/Web%20Porto%20React+Tailwind+FramerMotion%20-%20Copy/src/components/ContactForm.jsx#L49-L54)
* **Masalah**: Service ID, Template ID, dan Public Key ditulis langsung sebagai teks biasa di kode:
  ```javascript
  // ⚠️ Kurang aman jika di-push ke GitHub publik
  emailjs.send("service_7o8v44b", "template_3p4tls7", formData, "534efn26m_ApH_LyW")
  ```
* **Solusi Mentor**:
  Gunakan Environment Variables Vite.
  1. Buat file `.env` di *root folder*:
     ```env
     VITE_EMAILJS_SERVICE_ID=service_7o8v44b
     VITE_EMAILJS_TEMPLATE_ID=template_3p4tls7
     VITE_EMAILJS_PUBLIC_KEY=534efn26m_ApH_LyW
     ```
  2. Tambahkan `.env` ke `.gitignore`, lalu buat file `.env.example` sebagai dokumentasi template.
  3. Panggil di komponen:
     ```javascript
     emailjs.send(
       import.meta.env.VITE_EMAILJS_SERVICE_ID,
       import.meta.env.VITE_EMAILJS_TEMPLATE_ID,
       formData,
       import.meta.env.VITE_EMAILJS_PUBLIC_KEY
     )
     ```

#### B. Arsitektur Data vs Komponen: JSX di Dalam File Data Statis
* **Lokasi**: [src/constants/index.jsx](file:///d:/Documents%20D/Code%20Program/Websites/Website%20Porto%20Learn/Web%20Porto%20React+Tailwind+FramerMotion%20-%20Copy/src/constants/index.jsx#L110-L140)
* **Masalah**: Menyimpan JSX Element `<RiReactjsLine className="..." />` langsung di array data:
  ```javascript
  // Kurang ideal: Data bercampur dengan Presentational UI
  export const SKILLS = [
    { icon: <RiReactjsLine className="text-4xl text-cyan-400 lg:text-5xl" />, name: "React", experience: "6 months" },
  ];
  ```
* **Mengapa ini penting?**: Data murni (*pure data*) idealnya bisa diserialisasi ke JSON (misalnya kelak kamu ambil dari REST API database). Jika datanya tercampur sintaks JSX, data tersebut tidak lagi *reusable* atau *serializable*.
* **Solusi Mentor**:
  Simpan referensi komponen dan konfigurasinya:
  ```javascript
  // di constants/index.js (Pure Data)
  export const SKILLS = [
    { id: 'react', name: "React", experience: "6 months", icon: RiReactjsLine, color: "text-cyan-400" },
  ];
  ```
  Lalu render di [src/components/Skills.jsx](file:///d:/Documents%20D/Code%20Program/Websites/Website%20Porto%20Learn/Web%20Porto%20React+Tailwind+FramerMotion%20-%20Copy/src/components/Skills.jsx#L39):
  ```jsx
  const IconComponent = skill.icon;
  <IconComponent className={`text-4xl lg:text-5xl ${skill.color}`} />
  ```

#### C. Responsive Layout Bug pada Layar HP (*Mobile*)
* **Lokasi**: [src/components/ContactForm.jsx](file:///d:/Documents%20D/Code%20Program/Websites/Website%20Porto%20Learn/Web%20Porto%20React+Tailwind+FramerMotion%20-%20Copy/src/components/ContactForm.jsx#L78-L108)
* **Masalah**: `<div className="mb-4 flex space-x-4">` tanpa `flex-col` di layar kecil. Input `Name` dan `Email` akan terjepit berdampingan di layar selebar 360px.
* **Solusi**:
  Gunakan pendekatan *Mobile First*:
  ```jsx
  <div className="mb-4 flex flex-col md:flex-row gap-4">
    <div className="w-full md:w-1/2">...</div>
    <div className="w-full md:w-1/2">...</div>
  </div>
  ```

#### D. Navigasi Scroll: Manual JavaScript Offset vs Native CSS
* **Lokasi**: [src/components/Navbar.jsx](file:///d:/Documents%20D/Code%20Program/Websites/Website%20Porto%20Learn/Web%20Porto%20React+Tailwind+FramerMotion%20-%20Copy/src/components/Navbar.jsx#L23-L38)
* **Pelajaran**: Kamu menulis fungsi JavaScript `handleLinkClick` dengan `window.scrollTo` dan kalkulasi offset `-85px` agar konten tidak tertutup fixed navbar.
  Di era CSS modern, kamu **tidak perlu JavaScript manual** untuk hal ini! Cukup gunakan class utility Tailwind `scroll-mt-24` pada setiap `<section>`:
  ```jsx
  // Di Project.jsx
  <section className="pt-28 scroll-mt-24" id="projects">
  ```
  Dan di Navbar cukup `<a href="#projects">Projects</a>`. Browser akan menghitung offset secara otomatis dan performanya jauh lebih mulus.

## Modul 2: Cara Berpikir Pemrogram (Problem Solving & Logic to Syntax)

Banyak pemula langsung mengetik kode begitu punya ide fitur, lalu bingung ketika kodenya error atau rumit. Seorang *Senior Developer* memecahkan masalah dengan **4 Langkah Mental Model**:

```mermaid
flowchart LR
    A["1. Deconstruct (Uraikan Masalah)"] --> B["2. State Identification (Tentukan Data Berubah)"]
    B --> C["3. Pure Logic (Alur Algoritma)"]
    C --> D["4. Syntax Implementation (Bungkus ke Kode)"]
```

### Studi Kasus Nyata: Fitur "Modal Detail Proyek" di Portofolio Kamu

Mari kita bedah bagaimana kamu menyusun fitur modal di [src/components/Project.jsx](file:///d:/Documents%20D/Code%20Program/Websites/Website%20Porto%20Learn/Web%20Porto%20React+Tailwind+FramerMotion%20-%20Copy/src/components/Project.jsx) dari sudut pandang pemikiran logis:

#### Langkah 1: Deconstruct (Uraikan Kebutuhan Jadi Kalimat Biasa)
1. "Ada daftar kartu proyek."
2. "Ketika pengguna mengeklik salah satu kartu atau tombol detail, layar harus menampilkan jendela pop-up dengan detail proyek terkait."
3. "Selama pop-up terbuka, halaman belakang tidak boleh bisa di-scroll."
4. "Pop-up harus bisa ditutup lewat tombol X, klik di luar area modal, atau menekan tombol `Esc` di keyboard."

#### Langkah 2: State Identification (Data Apa yang Berubah?)
Tanyakan: *"Apa data minimal yang dibutuhkan React untuk tahu apakah modal sedang terbuka atau tertutup?"*
* **Salah**: Membuat boolean `isModalOpen` DAN state `modalData`. (Ini redundan!)
* **Benar**: Cukup satu state: `selectedProject`.
  * Jika bernilai `null` $\rightarrow$ modal tertutup.
  * Jika bernilai `{ id: 1, name: '...' }` $\rightarrow$ modal terbuka dan langsung tahu data apa yang harus dirender!

#### Langkah 3: Pure Logic (Langkah demi Langkah / Algoritma)
* *Trigger Buka*: `onClick={() => setSelectedProject(project)}`
* *Trigger Tutup*: `setSelectedProject(null)`
* *Side Effect (Kunci Scroll & Listener Keyboard)*:
  * "JIKA `selectedProject` ada $\rightarrow$ pasang event listener `keydown`, kunci `body.style.overflow = 'hidden'`."
  * "JIKA `selectedProject` null ATAU komponen unmount $\rightarrow$ lepas listener, kembalikan scroll."

#### Langkah 4: Syntax Implementation (Membungkus ke Sintaks React)
Di sinilah logika tersebut diterjemahkan ke hooks:
* Logika state $\rightarrow$ `useState(null)`
* Logika side effect & listener $\rightarrow$ `useEffect(..., [selectedProject])` dengan *cleanup function* di dalamnya.
* Logika render mengambang di atas DOM $\rightarrow$ `createPortal(..., document.body)`

> [!TIP]
> **Prinsip Emas Mentor**: *Jangan pernah menulis kode sebelum kamu bisa menjelaskan alur fiturnya dalam bahasa manusia secara runtut kepada anak umur 10 tahun.*

## Modul 3: Jembatan Menuju Proyek PERN (Inventory Management)

Proyek portofolio kamu adalah **Static Client-Side App** (datanya ada di kode frontend). Proyek berikutnya (Inventory Management) adalah **Full-Stack Dynamic App**. 

Berikut perbandingan pola pikirnya:

| Konsep | Di Portofolio Kamu Saat Ini | Di Proyek Inventory Management (PERN) |
| :--- | :--- | :--- |
| **Penyimpanan Data** | File statis `constants/index.jsx` | Tabel Relasional di **PostgreSQL** |
| **Operasi Data** | Hanya membaca (*Read*) via `.map()` | **CRUD** (Create, Read, Update, Delete) via SQL queries |
| **Komunikasi** | Langsung panggil variabel JavaScript | Frontend panggil REST API Backend via `fetch` / `axios` |
| **Validasi** | Cuma di form frontend | **Wajib di Backend** (mencegah manipulasi data & injection) |
| **Keamanan** | Tidak ada hak akses | Autentikasi (JWT) & Otorisasi peran (Admin vs Staff) |

---

### Arsitektur Dasar Proyek PERN yang Direkomendasikan

Agar kamu tidak bingung saat memulai backend nanti, gunakan pola arsitektur **Layered Architecture (Separation of Concerns)**:

```
[ Frontend: React + Tailwind ]
            │ (HTTP Request: JSON + JWT)
            ▼
[ Backend: Node.js + Express ]
   ├── routes/          (Menentukan URL endpoint, misal: /api/products)
   ├── controllers/     (Menerima request, validasi input, kirim response)
   ├── services/        (Logika bisnis, misal: cek apakah stok mencukupi)
   └── models/queries/  (Eksekusi SQL ke Database)
            │ (SQL Query)
            ▼
[ Database: PostgreSQL ]
```

### Langkah Persiapan Menuju Proyek Inventory:
1. **Rancang ERD (Entity Relationship Diagram)** terlebih dahulu sebelum menulis kode apapun:
   * Tabel `users` (id, username, password_hash, role)
   * Tabel `categories` (id, name, description)
   * Tabel `products` (id, category_id, sku, name, quantity, price)
   * Tabel `stock_logs` (id, product_id, user_id, change_type ['IN', 'OUT'], quantity, notes)
2. **Kuasai Asynchronous JavaScript**: Pahami `async / await`, `try ... catch`, dan bagaimana menangani status `loading`, `error`, dan `data` di React.
3. **Mulai dari Backend Terlebih Dahulu**: Bangun Express server, sambungkan ke PostgreSQL menggunakan *connection pool* (`pg`), dan uji seluruh endpoint CRUD menggunakan Postman atau Thunder Client sebelum mulai membuat halaman React-nya.
